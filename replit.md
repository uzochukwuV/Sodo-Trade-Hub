# Sogram — Workspace Memory

## Overview

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **API framework**: Express 5
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)
- **Frontend**: React + Vite + Wouter (routing) + TanStack Query

## Brand / Design System

- Background: `#0A0A0A` (pure black)
- Accent: `#D4FF00` (electric yellow-lime) — sole accent color
- Red (loss/pain): `#FF3B3B`
- Green (win/profit): `#22C55E`
- Typography: DM Sans (UI) + JetBrains Mono (numbers/code)
- Style: Ultra-thin 1px borders, sharp corners, uppercase labels, Codex.io aesthetic
- Dark-only app — no light mode

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
  - **CRITICAL**: After every codegen run, fix `lib/api-zod/src/index.ts` to only contain `export * from "./generated/api";` (orval regenerates a stale `api.schemas` export that breaks typecheck)
- `pnpm --filter @workspace/db run push` — push DB schema changes
- `/home/runner/workspace/node_modules/.pnpm/node_modules/.bin/tsx scripts/src/seed.ts` — run seed script (tsx is not in PATH, use full path)

## Architecture

### Packages
- `artifacts/api-server` — Express API, routes at `/api/*`, port via `$PORT`
- `artifacts/sogram` — React + Vite frontend, port via `$PORT`
- `lib/db` — Drizzle schema + DB client (`@workspace/db`)
- `lib/api-spec` — OpenAPI YAML spec (`lib/api-spec/openapi.yaml`)
- `lib/api-zod` — Zod schemas generated by Orval (`@workspace/api-zod`)
- `lib/api-client-react` — React Query hooks generated by Orval (`@workspace/api-client-react`)
- `scripts` — Seed scripts (run via full tsx path above)

### React Query hooks location
Hooks are in `@workspace/api-client-react` (not `@workspace/api-zod`).
Types/schemas are imported from `@workspace/api-client-react/src/generated/api.schemas`.

### DB field name mappings (copy configs)
DB uses: `followerId` / `maxPositionSizeUsd` / `stopLossPct`
Generated client uses: `copierId` / `maxPerTradeUsd` / `stopCopyDrawdownPct`
Mapping handled in `artifacts/api-server/src/routes/copy.ts`

### Placeholder IDs
- `CopyTrading.tsx`: `MY_COPIER_ID = 999`
- `PainRoom.tsx`: `MY_TRADER_ID = 17`
- `Intents.tsx`: `MY_VOTER_ID = 17`

## DB Schema Tables

- `traders` — profiles, rep score, tier, PnL, win rate
- `trades` — closed trades with PnL, txHash (on-chain verification), isOnChainVerified
- `signals` — open/hit/stopped signals with confidence
- `copy_configs` — copy trading relationships
- `pain_rooms` — verified loss posts (Pain Room feature), isAnonymous flag
- `breakdowns` — structured community responses to pain rooms
  - `what_failed` enum: `entry_timing | thesis | sizing | risk_management | exit_timing | leverage`
  - `signal_status` enum: `open | hit | stopped`
- `trade_intents` — pre-trade setups posted for community validation (Phase 4)
  - `status` enum: `open | closed_hit | closed_missed`
- `intent_votes` — voter records per intent (vote: `valid | invalid`)
- `rep_event_type` includes: `validation_correct | validation_wrong` (fires on intent resolve)

## Platform Analysis (updated May 2026)

### External APIs — Current State

**Sodex and SoSoValue are NOW integrated:**
- `artifacts/api-server/src/services/market.ts` — unified market service with 30s cache (prices), 5min cache (news/klines)
- **Sodex testnet** (`SODEX_BASE_URL=https://testnet-gw.sodex.dev/api/v1`): live perp ticker prices for BTC/ETH/SOL/BNB/ARB/OP/AVAX
- **CoinGecko** (free, no key): OHLC klines for sparkline charts (`/coins/{id}/ohlc`)
- **SoSoValue** (`SOSO_BASE_URL`, `SOSO_API_KEY`): crypto news feed for Market Vibe section
- **Market Vibe**: contextual mock text built from real prices + news (OpenRouter deferred)
- `txHash` column on trades: real 0x-prefixed hex hash, sets `isOnChainVerified=true`, displayed truncated in feed

### Market Service API Routes
- `GET /api/market/prices` — live Sodex ticker prices (30s cache)
- `GET /api/market/news` — SoSoValue news (5min cache)
- `GET /api/market/klines/:symbol?days=1` — Sodex native OHLC klines (5min cache, CoinGecko fallback)
- `GET /api/market/vibe` — summary + prices + news combined
- `GET /api/market/fills/:symbol?limit=50` — live Sodex trade fills (15s cache), returns last N fills with tradeId/time/side/price/qty
- `POST /api/trades/verify-sodex` — verify a Sodex trade ID against fills feed (checks side match + price within 2%)

### What Each External API Provides

**Sodex (integrated):**
- Live market fills per symbol: `/perps/markets/{symbol}/trades` — 50 recent fills, paginated by time
- Native OHLC klines: `/perps/markets/{symbol}/klines?interval=1h/4h/1d` — used for sparklines
- Tickers: `/perps/markets/tickers` — 30 markets, mark/index price, OI, funding rate
- Orderbook: `/perps/markets/{symbol}/orderbook` — available but not yet used
- **No per-account API** — fills are public market data only (no wallet-scoped history)
- Sodex trade IDs are large integers (not 0x hashes); `verifySodexTrade()` matches by ID + side + price ±2%

**SoSoValue:**
- Kline/chart data — entry/exit chart embeds on win posts and Pain Room cards
- Economic calendar — powers Market Vibe, contextualises Pain Room macro errors
- News/narrative feed — pre-market scroll content between trades
- Protocol TVL and ecosystem metrics — validates/invalidates ecosystem theses

### The 5 Emotional Pillars (Product Vision)

1. **Pain Room** — verified losses with structured community breakdowns ✅ BUILT + anonymous post toggle ✅
2. **Trade Intent Validation** — pre-trade setup voting (live votes, community pressure) ✅ BUILT
3. **Verified Win/Loss posts** — with txHash on-chain verification ✅ BUILT (Sodex hash + SoSoValue chart embeds pending)
4. **Market Vibe** — AI-generated hourly emotional market narrative
5. **Reputation as Identity** — multi-dimensional rep (win rate + signal accuracy + validation accuracy + mentor score + streak)

### Additional Mechanics Designed

6. **Streak + Streak Protection** — earned by helping in Pain Room
7. **Trade Confessional** — anonymous verified mode (partially in Pain Room already)
8. **Pre-market scroll** — Market Vibe + calendar + news between trades

### The Interconnection Map (key relationships)

| Feature | Feeds into | Draws from |
|---------|-----------|------------|
| Intent Validation | Pain Room context, Validation Accuracy rep | Market Vibe, Signals feed |
| Pain Room | Mentor rep, Streak protection | Intent Validation history, Sodex hash, SoSoValue chart |
| Signals | Signal accuracy rep, Feed | Reputation rank, Market Vibe |
| Copy Trading | Copier PnL, Transparency | Reputation dimensions, Pain Room history |
| Streak | Streak protection shields | Pain Room participation |
| Market Vibe | Feed context, Signal context, Pain Room context | SoSoValue calendar + news |
| Reputation (multi-dim) | Everything visibility/weight | All tracked actions |

### The Single Architectural Truth

**Every action must feed at least one other feature.**
The platform becomes sticky when closing a trade automatically determines what happens next
based on outcome — win → feed post + streak + rep update; loss → Pain Room option + streak check.
Reputation is the connective tissue. External APIs (Sodex/SoSoValue) provide credibility.
Emotional mechanics (Pain Room, Streak, Market Vibe) drive daily retention.
Transactional features (Signals, Copy Trading) drive monetisation.
